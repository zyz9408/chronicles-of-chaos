## 功能与数据一致性

- 恢复规则支持“血量、血条、生命值”；明确的新绝艺数值重新编译，手动确认规则仍保留。变量编辑重新编译已修改的描述。
- 否定使用不会触发恢复；日志记录真实恢复量及当前/最大值。
- 当前战斗使用角色真实生命/体力上限，百分比恢复按冻结上限换算；纯治疗绝艺不再继承合成攻击。
- 主动技能按使用、命中、暴击和攻击结束事件执行效果，遵守条件和次数限制；被动技能补齐受伤、闪避、格挡和倒地事件。攻击前临时修正不再永久累积。
- 写回重整合并实际变化的字段，保留同回合其他结算。回退、纠错与变量编辑检查预期存档状态，拒绝旧页面覆盖新进度。
- 云 API 配置支持 v3；本地替换导入先完整校验，再原子更新配置与路由。
- ZIP 导入在分配解压缓冲区前检查累计展开大小、单项大小、数量和路径。
- 全部数据清理覆盖独立 AVG 数据库、图像密钥、资源包目录和旧存档检查点。保留 API 模式也保留图像服务密钥。
- 资源包清理失败会保留索引以便重试，不再吞掉权限/I/O 异常。
- 云下载记住响应中的实际 revision。删除及替换的旧对象进入持久清理队列；重复删除不会重复扣配额，待上传槽位也计入限额。
- OAuth 返回路径拒绝反斜杠及控制字符；后台口令移到服务端 Secret。
- 增加重型校准测试专用超时、单 Worker 浏览器配置与 GitHub CI。升级开发依赖并重新安装锁文件。

## Cloudflare 发布顺序

1. 在发布新版 Functions 前，对绑定 `CLOUD_SAVE_DB` 的数据库应用 `migrations/cloud-saves/0003_atomic_cleanup.sql`。它添加事务内清理队列、删除配额触发器与并发槽位保护。不要对已应用的数据库重复执行 ALTER TABLE。
2. 配置服务端 Secret `ADMIN_ANALYTICS_PASSCODE`（至少 16 字符的随机口令）。不配置时后台统计拒绝访问。口令不应写入前端、仓库或普通公开变量。
3. 发布前端和 Functions。仅 GitHub Pages 的静态部署不会运行云端 Functions。

清理队列在该用户后续的云列表、上传或删除请求中重试（每次最多 32 个对象）。R2 短期不可用时索引删除已经完成，物理对象会留到重试成功；不宣称跨 D1/R2 的物理事务。

初次修复验收不包含线上数据库迁移、Secret 设置、推送或部署。随后经用户授权，发布目标确定为本仓库现有 GitHub Pages（`gh-pages` 分支）；它只发布静态前端，后端修复以源码交付，不执行原作者 Cloudflare 站点的迁移。生产大模块的进一步拆分属于后续性能工作，当前仍有包体积警告。
